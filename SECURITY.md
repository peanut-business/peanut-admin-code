# Security Policy

Security reporting does not require a private maintainer repository. Use this repository's private vulnerability-reporting entry when available. Otherwise send a contact-only request with the affected release and a private contact method; do not disclose the component, attack steps or diagnostic details publicly.

Never publish credentials, personal or tenant data, exploit code, raw logs, cookies or tokens in issues, pull requests or screenshots. Privately identify the exact affected source/release, prerequisites and minimum redacted reproduction. Only test systems and data you own or are authorized to test.

Ordinary defects follow the [support guide](docs/public/support.md). A source version string alone does not establish a published security-support guarantee.
