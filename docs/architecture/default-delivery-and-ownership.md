# 默认交付与职责

已生效。本文定义框架职责、默认与可选组合和生命周期；打包、安装和升级合同见[开发规范](../development/standard.md)，能力全集见[总览](overview.md)。目标不代表已有验收。

## 1. 总体决定与理由

采用 ThinkPHP 原生机制＋精简核心＋标准模块组合：安装后可用，不让开发者从零拼装；默认配备不等于塞进 Core，模块化不等于任意卸载。极简底座为高级用法，不作为默认；不建巨大 Core，不按概念层数增仓/拆包。

## 2. 框架与核心的责任

ThinkPHP 提供启动/容器/服务注册、HTTP/路由/多应用/中间件/CLI、Validator、ORM/事务、同步事件/配置/日志/缓存；Peanut 接入模块、可信身份、授权/Scope、数据归属、业务约束、防重复及失败处理。不得重造平行框架、逐表空 Repository 或机械包装所有第三方接口。

当前面向 ThinkPHP，不追求兼容所有 PHP 框架；接口/适配只用于真实替换、协议或安全边界。核心九组职责有真实实现但不含完整通用业务；账号、部门、文件等各有唯一模块/数据/服务/页面负责人，不复制、不长期双写，也不强制一功能一包。

## 3. 生命周期执行边界

| 阶段 | 允许工作／禁止混入 |
| --- | --- |
| 应用初始化 | 环境与公共服务/模块登记；不查当前用户、不执行安装 SQL 或业务写入 |
| 对象创建 | 注入依赖、轻初始化；不扣款/下单/通知 |
| HTTP 请求 | 建立身份/租户/追踪，核模块与权限/Scope，再执行业务；不保存长期身份快照 |
| 业务操作 | 校验、明确事务负责人、公开服务协作；不依赖未知监听顺序 |
| 模型操作 | 映射/局部数据行为；不隐藏完整支付/采购/调拨流程 |
| 后台任务 | 本次身份/范围、防重复/重试/清理；不继承上个任务的身份或事务 |
| 安装升级 | 预检、迁移、资源/版本登记；不在普通请求偷偷补装 |

装配决定入口存在，执行时检查租户可用性；不按租户反复改共享路由/监听。模块停用约束入口/任务/监听。HttpEnd 仅收尾，不代替可靠任务。Trait 复用代码，Attribute 声明元数据，必须有读取者执行，不自动授权。声明/发现/注册/有效/测试是不同状态。

## 4. 标准应用默认交付集合

| 默认能力 | 完整最小范围 |
| --- | --- |
| 账号登录 | 至少一种不依赖付费渠道的登录、会话、退出、个人账户和安全限制 |
| 租户成员 | 关系、状态；Standalone 默认租户 |
| 角色/范围 | 权限点、角色、当前租户 Scope、对象检查 |
| 部门/岗位 | 部门树、岗位、成员；可简单配置，不强制公司层 |
| 模块管理 | 安装/开通记录、依赖、有效状态 |
| 菜单/发现 | 入口、权限关联、客户端有效能力 |
| 设置/字典 | 通用设置、分组、参考数据 |
| 文件 | 受控上传/下载、登记/分类/权限、可用基础存储 |
| 服务策略 | 平台绑定、允许自定义等已定四策略 |
| 基础通知 | 站内、未读、基础消息定义，无须先配外部厂商 |
| 持久任务 | 记录、执行入口/进程、进度/结果、失败/重试查询 |
| 日志/审计 | 请求关联、关键安全记录、受控查询 |
| 语言/格式 | 资源、时区、日期/数值约定 |
| 健康/版本 | 版本、必要依赖与任务执行状态 |

默认安装不授予所有人使用权，不允许普通租户安装服务器代码或改平台秘密；基础安全/活动必需依赖不可随意停用，替换须受控装配/升级。认证基础不默认附会员余额/充值/积分/标签/供应商账期；公开注册和第三方登录按产品启用。

## 5. 按需装配集合

审批/工作流；导入导出（满足文件和任务依赖）；WebSocket/SSE；自定义调度管理（不同于任务执行基础）；短信/邮件/Push 适配器及凭据；第三方登录/API/Webhook；设备/AI 委托管理；高级参考数据版本/复杂报表；商品/订单/库存/采购/门店/仓储等行业模块。集团汇总暂缓。

可选不降低质量：未使用渠道不阻塞启动，但使用异步功能必须配真实执行器/恢复；入队不等于业务完成，不强制额外中间件或所有业务经过 Command Bus。

## 6. 独立应用与 SaaS

独立应用隐藏默认租户，共用安全与业务结构，不删 SaaS 源码维护分支。SaaS 默认加平台身份、租户初始化/生命周期、模块授权、服务策略、必要配额/健康、可信入口；套餐销售/订阅账单/在线支付按需，可先人工开户授权。

## 7. 前端与开发工具交付

提供四类官方工程，按产品清单构建部署：标准应用默认后端＋租户后台，SaaS 加运营平台，网站/小程序/App 按需。开发者中心默认进入开发交付，生产仅授权诊断/维护；UI/CLI 共用服务，不默认暴露源码编辑和任意安装。详情见[开发工具](../development/developer-center-and-documentation.md)。

## 8. 单一能力负责者

文件以真实现用应用链为基线，保留凭据路由、租户隔离、访问、素材关系、旧绑定和失败补偿；吸收有价值技术片段但最终一套账本/生命周期。身份组织等保留唯一实现/数据 ID/公开合同，迁移同时更新消费者。未采用能力说明未启用，不凭目录存在声称可用，不删代码制造零缺陷。

## 9. 开发装配与运行基线

本节公开已经确定的工程约定，不增加新的运行环境或宣布产品验收。后端基线是单部署单元、PHP-FPM/CLI/worker 8.3、ThinkPHP 8.1/ThinkORM 4、MySQL 8.4；精确补丁以本工程原生锁及实际加载为准，不把旧基线补丁或latest当作当前版本。分库、多方言和跨实例事务不作为默认能力。

| 工程 | 职责与技术边界 |
| --- | --- |
| platform | Vue 3 运营入口，与租户后台的构建、会话和权限分开，共用纯UI能力 |
| web | Vue 3、Vite、Element Plus、Pinia 租户后台，不自行复制认证与请求设施 |
| pc | Nuxt 3/Vue 3 网站，不是桌面软件；公开SSR与个人浏览器状态边界见[源码导读](../development/current-code-lifecycle.md#10-ssr与两种形态) |
| uniapp | Vue 3 uni-app；H5和已有微信小程序分别验证，其他平台不从一次构建成功推定 |

Node基线是22系列兼容补丁且至少22.12；实际版本、各工程packageManager与lock共同核对。按原生锁安装，不借规范迁移全面升级Vite/Nuxt/uni-app或替换UI框架。

PHP Core保留一个 `peanut-admin/core` 技术包，按职责分目录，不按概念拆成空包。Web Core使用自己的pnpm workspace，六包职责如下：

| 包 | 允许职责 |
| --- | --- |
| @peanut-admin/client | 框架无关传输、认证、错误与范围辅助；导入不访问Vue/DOM/uni或完整业务API |
| @peanut-admin/vue | Vue认证状态、模块和路由接入，依赖client并声明真实peer依赖 |
| @peanut-admin/ui-vue | 纯布局、表单、表格、主题和状态；UI框架依赖隔离在此 |
| @peanut-admin/nuxt | 请求级SSR客户端和环境适配，不含网站业务 |
| @peanut-admin/uniapp | 终端传输、存储等适配，不依赖桌面UI |
| @peanut-admin/testing | 有真实消费者的开发测试辅助，不进入默认生产运行依赖 |

业务页面、业务状态和生成SDK留在Code所属模块。内置文件API的选择器属于文件模块，纯选择控件可以属于UI；不能只凭是否含.vue决定归属，也不继续扩大旧 `@peanut-admin/admin`。

### 联合开发与发行安装分开

联合开发底座时默认直接消费选定的PHP Core和Web Core源码，沿现有开发连接机制核真实解析路径以及必需编译产物，不混用新PHP源码与旧Web归档。开发连接写入忽略的本地配置/依赖，不把个人绝对路径或开发链接写进发行锁；缺源码或构建失败明确报错，不静默退回旧包。正常开发允许未提交改动，本地源码版本不要求等于旧发行物版本；各应用与Core仍遵守各自原生包管理器和外部依赖锁，改动后重建受影响产物。制作可复现候选时才固定提交；编译成功不等于已经发布。

使用完整产品发行包的开发者不必取得底座联合开发工作区，更不依赖私有Project：按包内Composer/npm/pnpm锁装依赖即可继续开发。构建机器可安装依赖用于编译，但发行包不复制任何层级vendor/node_modules或缓存；开发源码、锁、浏览器产物、迁移、安装/升级入口、公开资料和许可证仍须保留。SSR服务端依赖由目标环境按说明安装和构建，不靠删除输出依赖伪装为可运行。发行渠道及完整产品验证是另一阶段，不是阅读本节就必须执行的任务。

## 10. 客户端地址、渲染与部署目录

默认同机同源交付，Web根只指向 `server/public`。物理产物目录为 `public/admin`、`public/platform`、`public/pc`、`public/mobile`；物理PC目录不代表网站使用 `/pc` URL前缀，网站默认根首页。只有明确完全不启用PC的纯管理模式，精确 `/` 才跳转 `/admin/`；其他未归属地址返回404。前端base、history、资源位置与代理配置一起核对，不能只移动dist或因目录规范重定既有URL。

`/adminapi/*`及已登记的API、安装、回调前缀由PHP处理；页面回退与API分开，API404不能返回前端HTML，缺失静态资源保留真实404。源码、依赖与锁、工具、秘密、上传执行权限和SSR服务端均不进入公开资产目录；禁止通过上传PHP获得执行能力。新增或改变已确认的地址映射须明确决定。

普通新业务页面默认CSR，只有登记的首页、资讯列表/分类/详情、关于我们等公开页启用SSR；个人登录、头像、资料、收藏状态在浏览器取得，公开HTML及payload不携个人凭据。hybrid保留请求级SSR能力，不以全局默认SSR加少数私有页例外代替公开页清单；SPA使用同一源码的完整静态输出和真实PHP API，不运行PC Node，不能把hybrid的public子目录冒充完整SPA。SSR形态由同机Node服务及代理接入，不将SSR降为SSG或另造运行框架。

改变源码后重建受影响客户端，常驻worker受控重载；模块开通/停用属于运行授权，不能为单一租户反复改共享路由。这里定义开发与交付合同，不表示任何形态、浏览器或部署已经验收。
