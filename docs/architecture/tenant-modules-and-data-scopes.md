# 租户模块授权与 Scope

已生效。Scope 为服务端核验后的数据范围，不是登录身份或业务表。当前只支持同库授权读取机制，不据此宣称集团或跨实例能力已经实现。

## 1. 租户没有固定业务类型

独立开户客户对应租户，不是每个业务顾客/供应商都开户。无 tenant_type、库存型/集团型特殊分支或强制类型模板；功能由当前许可证引用的套餐决定，套餐包含共享模块及权限组合明细。A 可库存，B 可门店＋仓储，C 可采购＋批发，G 可汇总；同租户可多能力。租户只有一个当前许可证，期限或暂停状态不改租户身份；成员角色仍须在套餐上限内授权。Standalone/SaaS 为实例形态，不是租户类型。

## 2. 公司与集团的当前范围

不建租户内多经营公司层或以部门替外部客户开户；租户内有组织/岗位/角色及模块资源。公司名可为资料，客户/供应商公司档案不自动成租户。

集团 G、独立公司 A/B 是并列数据边界，关系不自动授权。集团汇总/组织查看/财务/跨公司写入暂缓；未来用普通租户的模块、租户后台与受控 Scope，不加超级租户/第五前端/第三形态。

开户方、付款方、代运营方可不同；按独立数据管理/生命周期开户，名称不能证明授权。组织节点无法代替对租户管理员也独立的隔离；仅禁“公司”名称无法防再包装 SaaS，开户/配额/代授权分别处理。

## 3. 四种事实分别判断

代码已安装≠租户已开通≠人员/设备/委托有动作权≠数据获准。代码依赖只要求实现兼容；业务开通依赖明确要求使用租户具备对应功能。G 读库存汇总不需获入库/出库权，来源 A 仍需库存模块与有效数据共享。正常订单声明依赖商品/库存时，不得以“代码存在”跳过开通。

## 4. 一个 Scope 机制，两种数据范围策略

普通入口：当前租户＋人员范围。声明支持的跨租户只读入口：核模块/人/来源授权后，以本次授权来源条件替换默认租户等值；不取消 Scope，不将 `tenant=G` 再与 `tenant in(A,B)` 错误相交，不改身份/数据归属，不冒充来源人员。

统一在查询构造/执行边界应用完整范围，禁止先暴露无约束查询再由业务补条件。可复用原查询实现，不公开关闭全部过滤的开关；不强制两策略各成包/类。

## 5. 授权不是单纯一份租户名单

每份授权表达来源/接收租户、双方功能/公开能力、动作、对象、字段/指标、状态/期限、来源及修订；不是客户端列表或集团名称。G 开消费汇总功能、A 开数据提供模块，不能强制两端相同模块。

例：A→G 仅中央仓数量；B→G 仅周转仓数量；A→G 部门名/人数但不含敏感个人信息。库存获准不代表订单获准；来源和对象保持配对，局部 ID 重复时必须带来源租户，未来跨实例还要实例身份。

同条件可用 `tenant_id IN(A,B)`；不同条件用 `(A AND A对象) OR (B AND B对象)`，再加其他业务约束。字段按来源/对象保留，不跨对象拼通行证；查询只返回获准字段/指标。已实现 requestedFields 等局部行为以当前源码核验，不从设计推定数据库通过。

## 6. 请求、参数和范围示例

```text
验证请求（当前 G）→检查 G 的汇总功能及人员/设备/委托权限
→核来源授权，生成本次 Scope→来源模块公开查询（范围＋日期/仓库参数）
→限制输出→记录访问依据，不记秘密。
```

来源/仓库参数只表达选择，不是授权；来源列表不固化成长期 Token。范围由服务端生成，身份始终属于 G。任务自行恢复/清理上下文，不设临时全局过滤开关，也不为 Scope 新建微服务。

## 7. 必须保留的边界

- 来源有权者批准，接收方有模块/动作权限；平台代授权需明确委托/期限/审计。关联不授权，不默认转授/写权限。
- 无授权、空范围、过期/撤销、未知策略或无法核状态即拒绝，不能退化成全部数据。显式请求未授权来源清楚拒绝；省略筛选仅使用已获准默认集合。
- 关联/子查询/排序筛选/分页/计数/汇总/导出均保留来源、对象、软删除和状态条件；跨模块只走公开服务，不读私表。
- 同动作允许在其绑定范围内并集，同对象 deny 优先；缓存先授权，键含接收方、实际人员权限、能力、来源和影响结果的修订，不能只用“集团报表”。
- 请求/任务/实时消息/结果文件读取均核最新授权/模块状态；长任务开始、提交批次及交付前复核，失权停止新操作，拒绝失权后的旧结果下载，保留已提交审计。
- 同库受限 SQL 不自动适用于分库/实例；后者须受控服务/获准投影，当前暂不产品化。输出声明指标口径、时间与新鲜度；撤销无法保证外部已导出副本消失，历史保存规则需明确。

## 8. 责任与验证

Core 管范围表达与强制执行；通用授权模块核身份/授权并生成范围；来源模块管限定查询；汇总模块管关联需求、指标和界面。验证覆盖双租户同局部 ID、双方模块、字段/对象、join/subquery/page/count/aggregate、deny、撤权、缓存、任务和结果交付；不以规则存在当作实现已经通过。

批量入口需要包含该API的Core版本：本轮固定开发候选为5.0.3-alpha.2，尚不代表公开发行或宿主默认Core已自动升级。实际消费须显式采用包含该API的固定Core。批量统计多个受保护资源时，使用 Core `DataPermissionEngine::queryConstraints(context, [resourceKey => operationName])`，将返回的每个约束分别交给原生 `ThinkPhpQueryConstraintApplier`，用于对应资源的列表和聚合。该入口只复用本次计算的模块、权限和目录修订，各操作的策略修订、有效期、目标基数及租户约束仍独立校验；指定目标仍使用 `queryConstraint`。独立调用重新读取，不建立请求级或跨请求授权缓存。Identity `TenantEntitlementService::permissionProjection` 同一次调用返回许可内模块与权限，宿主登记子集检查复用这份模块投影。

普通API及批量业务权限判断由Host在同一调用内取得已受许可限制的有效权限，并仅校验候选权限的实际模块owner；复用原生installedModule验证版本/schema/manifest，不枚举无关模块。成员权限判断仍重新读取活动成员、凭据及授权修订，但不额外读取界面角色名称和可切换租户数量。Identity许可查询已带回套餐修订，revisionFacts复用同一行，不再次读取相同套餐。独立调用不持有权限或许可快照。
