# 身份、组织与执行信息

已生效设计。账号、会话与执行上下文遵守[开发规范](../development/standard.md)，Scope 见[范围专题](tenant-modules-and-data-scopes.md)；实现与验收以实际源码和运行结果为准。

## 1. 四个概念

身份回答谁调用（人/设备/程序，可并行）；租户回答独立客户的数据空间；业务对象回答操作什么；角色＋范围回答允许什么动作/数据。Instance 是部署，Platform 是当前实例运营范围，不自动跨实例/租户。缺租户不是全租户权限。

## 2. 人员、终端、程序与业务关系

人员可有平台、租户员工、客户、合作方身份及多个租户关系；认证边界中的全局账号不等于全产品/实例共享身份。共用认证机制、安全域/会话独立，显式验证后关联，不按电话/邮箱/姓名合并；关联不串权限，保留历史 ID。客户/供应商档案可无登录账号，联系人登录不自动开户或获员工权。

业务主体=个人/组织；客户/供应商/合作方是可并存的业务关系，不是权限角色。平台支持/代运营须有目标、来源、期限、范围、撤销与审计，不天然进入客户业务。

## 3. 部门、岗位、角色和数据范围

部门/组织单元表达归属与分工，岗位表达职责，角色表达动作，范围绑定这份授权的对象。部门管理某资源不代表部门成员都能操作；岗位映射角色必须可追溯并定义变动/撤销，不能按名称判权。

例：张三“审核＋S1”“查看＋S2”，不能组合成“审核 S1/S2”。保留授权来源与范围；同动作允许按范围并集，同对象明确拒绝优先。临时/继承/撤销/缓存按统一授权机制，不留隐式权限。

## 4. 人员和终端的共同处理

| 场景 | 身份与限制 |
| --- | --- |
| 网页后台 | 员工；普通浏览器不强制独立设备凭据 |
| 人工 POS | 收银员＋登记设备；同时受人和设备范围约束，换班不继承上一人 |
| 自助收银 | 可匿名/登录顾客＋受限设备；按适用的各自权限 |
| AI 代人执行 | 实际程序＋被代表人；明确动作/租户/对象/期限/撤销，不复制万能员工 Token |
| 自动同步 | 服务账号自身授权，不虚构在线人、不永久绑定离职员工会话 |

并非每次同时认证两种主体；权限不超过适用的人/程序/委托上限。记录实际执行者、客户端/设备、被代表者。

## 5. 令牌、请求上下文、业务参数分开

| 信息 | 归属 |
| --- | --- |
| 人/程序、可信设备、租户关联 | 验证后的 Token 或服务端会话；不必全写进 Token |
| Token 编号/签发/过期时间 | 凭证生命周期 |
| 请求编号/服务端接收时间/追踪 | 本次执行上下文 |
| 单据、仓库/门店、源仓/目标仓、数量 | 业务参数 |
| 本次可操作范围 | 服务端核验动作、对象归属与授权所得 |

只设统一请求/执行上下文，不平行建万能业务上下文；模块可封装已验证业务输入。令牌编号≠请求编号，签发时间≠请求时间；登录不是永久授权。设备仅准 W1、参数选择 W2 时拒绝；同租户选仓不必换 Token，切租户须重验授权。G 获准读 A/B 时仍是 G 身份，不切成来源员工。

每请求/任务建范围并 finally 恢复，worker 不沿用上次身份/事务，任务不保存秘密 Token。具体读取器可复用，身份快照不能跨请求缓存。

收货例：验证凭证→建立本次上下文→校验单据/仓库/数量→在租户范围读取→检查动作与仓库权限→检查单据既定仓库→采购公开服务处理→审计关联人/机/单据/仓库。仓库参数不能覆盖单据业务约束。

## 6. 业务工作区与代码工作区

业务工作区=客户端内围绕工作组合的菜单、页面、动作、布局和默认选择；也可由独立客户端承载，不默认等于客户端/子租户，更不产生权限。例：租户后台→仓储工作区→本页 W1。偏好不是授权，多标签分别选 W1/W2，逐请求提交/验证，不以全局“当前仓库”串操作。

代码工作区仅指源码检出的开发目录。未来需要独立成员或数据的协作空间，由业务模块另行建模，不从界面工作区推导。

## 7. 业务主体、资源与关系数据

主体是业务对象的一类，门店/仓库为资源，货架/库位为内部位置，订单为单据；组织树、业务关系和集团关系不是一棵授权树。当前不设租户内经营公司或隐式子租户。

关系示意：`(tenant_id,store_id)` 与 `shelves.store_id`；`(tenant_id,warehouse_id)` 与 `locations.warehouse_id`；需要时模块维护 `party + business_relation`。用普通表/关联，不每资源建表；外键/唯一约束核租户一致。跨模块走公开服务；共用客户/供应主体模块属后续业务取舍，不预建万能资源表或强制公司层。

## 8. 统一资源引用与审计

公共引用为租户＋登记对象类型＋ID，不携 ORM/任意表名/类名，不授访问权。所属模块的受控摘要服务先授权再查当前资料。

审计保存当时可读摘要及必要前后变化，不能拿当前名称冒充历史，原对象删除后仍应可解释。调拨可同时关联单据、源 W1、目标 S1；只留必要信息，排除秘密/过量个人资料，脱敏并限制读取。

## 9. 验证

覆盖离职/角色撤销、设备禁用、委托过期、租户暂停、模块停用、伪造 ID/跨租户、双标签切换、调拨两端权限、删除后审计可读性。设计列出不等于测试已经执行。
