# 文件可见性与受控源站

业务只保存稳定的 `file_key`。公开/私有切换不改变句柄、已登记引用或已有不可变文档版本；解析预览、下载原件与管理资源仍分别授权。修改数据库的可见性字段不能代替关闭物理源文件。

## 可准入的源站

目标必须是受控的 private local 空间。本地源从 public local 迁入；七牛源当前支持华北 `cn-north-1`（Kodo `z1`）的 S3 下载域名。七牛的上传地址与下载地址是两个配置：

| Space 字段 | 示例及用途 |
| --- | --- |
| region | `cn-north-1` |
| endpoint | `https://up-z1.qiniup.com`，Kodo 表单上传 |
| access_domain | `https://example-bucket.s3.cn-north-1.qiniucs.com`，该 Bucket 的 S3 下载源站 |

存储账号使用正常加密保存、按当前请求解析的七牛 AccessKey/SecretKey。S3 下载由官方 AWS PHP SDK 以这些显式凭据签名；不会发现桌面配置、环境凭据链或实例元数据身份。Kodo 上传、stat 和精确对象删除继续使用七牛原生协议。传输保留严格 TLS、禁止重定向、有限重试、超时与受控下载文件语义。

预检查从供应商读取 Bucket 的公开属性、region 和 `versioning=false`，分别查询自定义源站域名及按 Bucket 筛选的 CDN 域名。当前源站关闭适配要求这两组域名为空且分页完整；已有绑定、未知状态、启用版本管理、其他未支持区域/供应商都拒绝整批准入，不能用一项配置布尔值宣布合格。这与七牛目前[不支持文件版本管理](https://developer.qiniu.com/kodo/kb/12957/kodo-nomarl-faq?category=kb)的合同一致，不把“不支持版本列举”推断成其他供应商没有历史版本。

## 批次与恢复

上传拒绝外层数据库事务；先保留带原请求身份的审计意图及 `pending_write` 对象账本，再调用供应商写入。供应商未返回确定成功，或成功后账本确认失败时，保留同一 key、大小和 SHA-256，能记录时进入 `write_failed`；不自动删除或重传。数据库不可用时，原意图和预留记录仍是对账依据，不能把未知结果当作对象不存在。先只读核对原 key；新的上传会生成另一个 key，不能用它代替恢复原上传。已确定成功后的交付或素材元数据失败补偿是另一条路径，只针对同请求的新对象，仍须遵守实际资源的精确删除授权。

预检查聚合选中源文件及其衍生物闭包，核当前管理权、修订、引用、存储配置、源对象大小/MIME/ETag 和目标不存在。ETag 只是供应商修订标记，不能当作 SHA-256。确认凭据绑定这些事实；提交前重新核供应商事实，再在短事务中锁定并复核整个批次。供应商 HTTP 不占用该准入事务的行锁。

接受批次后，先限制公开交付，再使用现有存储驱动下载/读取原件。受保护副本必须通过原登记 SHA-256、实际大小及文件内容 MIME 核验，才 CAS 切换位置。随后重新核源对象并只删除被冻结的原 key，确认其不存在；七牛还需实际验证原 S3 地址拒绝匿名读取。完成态保留私有副本，并按当前权限重新解析交付地址；旧网关令牌不能凭原公开状态继续读取。

每一步先持久记录意图，再执行外部操作和记录回执。超时或未知结果先查询原批次，按同一来源/目标和原请求继续；不能新建批次、重复上传或盲删。失败保持受限待处理，不自动恢复公开。已完成请求可观察自己的持久回执，不依赖已退役的原存储凭据重新执行。

应用的不可变历史、当前/历史引用和派生文件必须保留；不能把应用历史当作待删云版本。原源站删除只发生在字节相同的受保护副本已核验之后。已下载副本、第三方抓取及系统之外的缓存无法保证追回；当前未实现绑定 CDN 的失效适配，不能宣称这类源站已完成私有化。

这些是生产者的准入与恢复合同；离线协议检查不证明真实 Bucket、源站删除或运行资格已经验收。
