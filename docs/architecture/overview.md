# 总体能力地图

本文描述公开能力范围，不是功能完成清单。工程合同见[开发规范](../development/standard.md)，默认装配见[默认交付](default-delivery-and-ownership.md)；实际能力以源码、清单和运行结果为准。

## 1. 产品与作用域

Peanut Admin 是 Scope-Aware（作用域感知）的通用应用底座＋官方管理/用户端；Standalone 与 SaaS 共享核心、业务模块及租户安全合同，不维护两套业务分支。后端经稳定 API/SDK 供四类官方或第三方前端使用，不绑定某套页面；后端不绑定前端，不等于 PHP 必须兼容所有框架。

Instance=实际部署；Platform=当前实例的租户登记/运营配置；Tenant=独立客户的数据空间。平台不天然跨实例或读取租户业务。Standalone 使用隐藏的默认租户；SaaS 显式管理多个租户。Tenant 为第一等 Scope，业务模块必须 Scope/Tenant-Safe；切换形态仍需迁移验证。

租户无固定业务类型，其能力来自模块授权；不建租户内多经营公司层。部门/岗位是组织关系，门店/仓库/品牌/站点由模块定义，可有多个，只需一个时默认选中；均不是子租户。仓库等通过业务参数传入，不固化进 Token。集团功能暂缓，未来通过普通租户和授权读取 Scope 取获准来源数据，不取消过滤、不继承超级权限。详见[租户与范围](tenant-modules-and-data-scopes.md)。

## 2. 后端核心九组能力

核心不理解商品、订单或门店等业务，不依赖页面；启动、容器和 ORM 等复用 ThinkPHP。九组职责不是九个包，也不是只有接口的空壳；当前 PHP 单包，完整通用业务归 Code。

| 能力组 | 固定职责 |
| --- | --- |
| **执行内核（Kernel）** | 应用启动、每次请求／任务的上下文、生命周期、统一错误与基础扩展点；核心源码不用 `runtime/` 命名。 |
| **作用域机制（Scope）** | 解析、传递和验证租户等明确范围；区分实例部署、平台管理与租户业务归属；不内置仓库、门店模型。 |
| **身份上下文（Identity Context）** | 表达已验证的人员、设备、程序及委托关系；不直接管理用户页面。 |
| **授权基础约定（Authorization Contract）** | 提供动作与对象访问检查入口；角色、授权范围和管理 API 由通用能力提供。 |
| **模块接入内核（Module Kernel）** | 模块登记、发现、加载、依赖和生命周期机制；不在每次请求任意执行未登记代码。 |
| **基础设施接口（Infrastructure Contracts）** | 对接数据库、缓存、存储、队列、锁、消息和事件；优先使用框架既有能力，不另造平行框架。 |
| **配置读取机制（Configuration Context）** | 环境、实例、租户配置的读取约定；策略、秘密和覆盖边界明确，禁止无条件覆盖。 |
| **执行追踪机制（Observability Context）** | 请求／任务编号、结构化日志、安全审计关联及基础度量；不把令牌编号当请求编号。 |
| **兼容性约定（Compatibility Contracts）** | 底座、模块、客户端之间的版本、协议、能力声明和兼容检查。 |

## 3. 通用业务能力

通用能力=后端实现＋标准 API＋可选管理页面；行业规则归业务模块。以下地图不表示全部默认必装，实际装配见[默认交付](default-delivery-and-ownership.md)。

| 能力域 | 固定内容 |
| --- | --- |
| **账号与认证** | 账号、登录、登出、密码/凭据、会话、验证码、多端登录控制、第三方身份接入的统一入口。 |
| **用户与人员** | 用户资料、状态、人员基础信息、用户与租户/组织关系。 |
| **组织与部门** | 通用组织树、部门、岗位/成员关系；行业特有组织结构仍留给业务模块。 |
| **角色与权限** | 角色、权限点、数据权限策略、授权关系、权限查询与管理 API。 |
| **菜单与功能导航元数据** | 管理端功能入口、菜单/导航定义、前端能力声明；不把具体页面实现塞进后端 Core。 |
| **系统设置与参数** | 平台级、实例级、租户级设置，参数分组、可见性和 Scope 覆盖。 |
| **字典与基础参考数据** | 通用字典、枚举/参考码、地区等可配置基础数据。 |
| **文件与媒体** | 上传、下载、文件元数据、媒体管理、访问控制、Scope 隔离、存储驱动接入。 |
| **消息与通知** | 站内消息、通知模板、通知投递；Email、SMS、Push 等通过通道适配。 |
| **实时通信** | WebSocket/SSE 等实时消息能力以及连接身份/Scope 绑定。 |
| **任务与调度** | 定时任务、异步任务、任务状态、重试、执行历史；底层队列契约属于 Core。 |
| **工作流基础能力** | 通用审批/流程编排、状态流转和任务节点；具体行业流程由业务模块定义。 |
| **导入与导出** | 通用数据导入、导出、模板、异步处理、错误回执。 |
| **审计与操作日志** | 登录日志、操作日志、安全审计、变更追踪、关联 Trace。 |
| **Webhook 与外部集成入口** | Webhook、回调签名、外部系统接入、集成凭据引用和事件投递。 |
| **国际化与本地化后端支持** | 多语言资源、时区、Locale 等服务端基础支持。 |
| **功能开关与能力发现** | 查询已安装模块、租户模块授权及可用能力；产品形态与功能开关不产生固定租户业务类型。 |
| **模块管理** | 分开管理实例安装、租户开通、人员授权；依赖区分代码服务与租户业务依赖，底层机制由 Core 提供。 |
| **健康与运维信息** | 健康状态、版本信息、依赖状态、基础诊断和只读运维信息。 |

横向支持平台/租户服务使用策略、人员/设备/外部程序/AI 委托；开发者中心属于维护工具，不是第五类业务前端。账号基础不等于会员余额、积分或供应商账期等业务。

## 4. 模块基础能力

业务模块包括商品、订单、内容、客户、库存、采购、门店、会员、营销和仓储等；具体下游产品通过模块组合形成，不是核心内置业务。前后端源码各在正常工程，以同一模块编号汇集发布；可只提供后端或部分客户端，不承诺免构建热更新。

| 模块基础能力 | 固定要求 |
| --- | --- |
| **模块说明与登记** | 稳定编号、名称、版本、能力、来源与各端入口；不是用户登录身份。 |
| **数据归属声明** | 明确平台管理、租户业务或实例状态归属；租户业务拒绝缺失、伪造的租户范围。 |
| **依赖声明** | 声明底座、通用能力、其他模块的版本与能力要求；依赖无环。 |
| **后端登记** | 声明接口、公开服务、监听者、任务及权限点；按受众组织入口。 |
| **数据结构与迁移** | 自有结构、初始数据和升级步骤可追踪；已应用迁移不随意改写。 |
| **资源归属** | 声明自有表、文件、缓存前缀、任务、配置及外部资源；不读写其他模块私有表。 |
| **权限点** | 模块声明能执行哪些动作，通用系统决定授予谁及哪些范围。 |
| **设置项** | 声明配置作用范围、默认值、敏感性与允许修改者。 |
| **事件与扩展点** | 事件表达已发生事实，任务表达执行意图；具体时机、可靠性和错误处理见专题。 |
| **各前端贡献** | 可选提供运营平台、租户后台、租户前台、租户应用入口；源码分别存放。 |
| **导航登记** | 提供菜单、路由和权限关联；页面是否显示不能代替服务端授权。 |
| **多语言资源** | 模块自己的语言文本和格式约定随模块提供。 |
| **生命周期** | 区分发现、安装、租户开通、人员授权、停用、升级、卸载和数据清理。 |
| **兼容要求** | 声明适用的产品形态、底座、API 和客户端能力。 |
| **运行追踪** | 任务、错误和关键操作接入统一日志、审计和健康机制。 |

模块是交付单元，插件是扩展用法，共用一套登记/安装；内部不分发功能无需机械拆包，跨模块必须公开合同。调用/依赖/打包规则见[模块与交付](module-development-delivery.md)。

## 5. 四类前端与产品形态

| 前端 | 使用者与完整职责 |
| --- | --- |
| 运营平台 | SaaS 运营者：平台身份/权限，租户创建/开通/停用/归档/初始化状态，套餐、配额、订阅/账单、模块授权、域名入口、平台/默认配置、获准运营统计/审计、健康/版本/运维、平台通知/公告。默认不处理租户日常订单等；支持访问需独立授权。 |
| 租户后台 | 员工：人员/组织/岗位/角色，设置/字典/文件/通知/任务/日志，已开通模块业务、前台/应用运营配置；可看策略允许的套餐/配额/订阅或自助操作。授权汇总仍受来源 Scope，不取得来源管理权。 |
| 租户前台 | 访客/用户：普通 Web、企业/机构官网、品牌/营销落地页、内容/资讯、商城/交易、门户/服务网站、SEO SSR/SSG、登录后的账户/会员/订单中心；可纯公开或兼有用户区。 |
| 租户应用 | 终端用户：UniApp；微信/支付宝/抖音等小程序；iOS/Android；Flutter/React Native；PWA、应用型 H5 和其他终端。共享 API/身份，按栈复用 SDK，不承诺 Vue 组件通用于原生端。 |

SEO 是前台实现要求；用户中心默认在前台或应用，不新增第五类；业务确需独立门户时再拆。覆盖范围不等于当前版本实现所有框架，具体支持目标以各客户端声明为准。

Standalone 不暴露租户选择、生命周期、运营及套餐订阅概念，但保留同样隔离、通用管理和转换基础。SaaS 能力地图包含租户初始化/生命周期、平台身份/权限、模块授权、配置/入口、套餐、配额、订阅、计费/账单接口与状态、运营查询/审计及隔离。基础运营必备，在线商业能力按需；SaaS 后端形态不是运营前端本身。

## 6. 前端公共能力二十组

具体业务 API/SDK、页面、权限常量、菜单及业务状态归 Code 模块；Web Core 只承载下表通用设施及对应环境适配。

| 前端基础包能力 | 固定职责 |
| --- | --- |
| **HTTP 请求与传输适配** | 超时、取消、请求头、错误映射和安全重试；非幂等操作不能盲目自动重试。 |
| **接口客户端与类型** | 由 OpenAPI 等正式接口定义生成／维护类型和调用入口。 |
| **认证与会话** | 登录、刷新、退出和多端会话；不把秘密密钥下发前端。 |
| **租户选择与请求关联** | 传递候选租户选择和追踪信息，由服务端认证；业务对象仍走参数。 |
| **前端访问控制辅助** | 权限点、能力、路由与组件可见性；不替代后端授权。 |
| **环境与部署配置** | API 地址、公开客户端配置和功能开关。 |
| **公共状态基础** | 共享初始化、持久化和状态约定，不保存单一业务页面状态。 |
| **路由与导航辅助** | 登录跳转、权限导航、路由守卫；页面由对应客户端拥有。 |
| **错误与提示** | 统一认证错误、权限错误、业务错误和恢复提示。 |
| **文件上传下载** | 进度、文件访问、上传和下载接口。 |
| **实时连接** | WebSocket／SSE 的身份绑定、重连和租户隔离。 |
| **通知客户端** | 通知读取、未读状态和消息通道接入。 |
| **国际化与格式化** | 语言资源、时区、日期、数值等显示。 |
| **功能与能力发现** | 查询形态、模块开通和后端支持能力。 |
| **模块前端接入工具** | 模块注册、扩展点、菜单和页面贡献。 |
| **前端运行观测** | 追踪关联、错误报告、基础性能及受控埋点；保护用户隐私。 |
| **本地缓存与存储** | 命名空间、会话切换清理和租户隔离。 |
| **主题与基础组件** | 设计变量、无行业语义的基础 UI；不同框架分别适配。 |
| **表单表格与数据工具** | 校验、分页、筛选、数据转换等公共能力。 |
| **开发测试工具** | 模拟调用、契约检查和公共测试辅助。 |

## 7. 组合关系

```text
ThinkPHP → 技术 Core → 通用/行业模块 → 稳定 API/SDK
                                             ↓
                        运营平台｜租户后台｜租户前台｜租户应用
产品清单：选择形态、模块/版本、客户端、品牌与默认配置。
维护体系：开发者中心、中文规范、自动目录、测试与交付工具。
```

图是职责关系，不是强制调用栈；仓/包/层/数据库/进程数量无须一致。详细正文由[文档目录](../README.md)定位；不复制能力地图为另一份计划。
