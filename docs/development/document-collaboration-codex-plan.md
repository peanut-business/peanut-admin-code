## A. 最终目标与范围

本轮工程终点是：标准业务文档、内容工具与富文本多人协作可在隔离开发/测试环境真实使用；文档与文件权限正确；既定资源阶段一有可核验的接收/完成结论；两种 Edition、可选协同服务与独立 CLI 的必要链路通过；源码、合同、迁移与证据正常进入相应 dev，临时现场完成收口。**不是自动公开发行或生产上线。**

### C.1 默认调度与集成顺序

推荐批次：G0 →（R0 + T0）→（B1 + B2/B3 非重叠准备）→（C1 + 已定协议的 C2 准备）→（C2 集成 + D2 非重叠 UI）→ D1/D2 → E1 → E2/F1 → Q1 → Z1。R1 可以作为 File 原任务继续并行，或在 File 写集空闲且授权明确时由同一执行主控接收；进入整体完成前必须有明确验收结论。

这不是让同仓同时跑全部工作包。最多两个执行子任务；共享 schema/DTO、module.json、package/lock、路由、迁移、清单和集成分支均由指定唯一 owner 写入。可并行的条件是依赖稳定、文件不重叠、可变资源不冲突，而不是模块名不同。

没有可用子代理/额外工作树容量时自动串行，完成标准不变。已有 038、其他界面修复或 File 执行现场不得仅因空闲 Job 被删除；确认原 owner/Session 的阶段终态才可回收。

## D. 执行主控与连续推进

产品决定与最终审议由当前 039 对话维护；交给本地 Codex 后，**Codex 主会话成为本轮唯一工程调度、集成和状态写入者**。当前对话不并发修改它占有的源码/索引，也不要求 Codex 每个阶段回到网页等待批准。子代理/子会话只提交有边界的成果，不能另定产品原则或再次无限分派。

主循环：读取当前 checkpoint → 找到依赖满足且写集空闲的任务 → 派发或本机执行 → 核真实退出/产物/差异 → 修复与受影响重验 → 集成并更新记录 → 继续下一就绪项。阶段完成不是整个任务结束；只有 Z1 成功、用户明确停止，或剩余所有任务都由真实硬阻塞卡住时，才停止当前执行并给准确终态。

最多两个子任务不是要求两个都始终运行。Code 同仓容量不足时一个写入任务配只读审阅，或串行；不得为了并行绕过全工作区上限。主控在受检输入上持有唯一集成权，不允许多个主控同时提交相同 dev。

## E. 检查与完整验收

各任务先使用仓库已有工具/lock/原生测试；新功能缺测试时补真实断言。一般流程为：静态/类型/格式 → 精确能力合同 → 真实集成 → 最终受影响组合验证。不把每次文件编辑变成整站 build，不用新增空消费者重复旧有效资格。新 schema、跨进程协议、依赖锁或构建入口变化才使其相关证据失效。

| 验证组 | 必须证明 |
| --- | --- |
| 文档与权限 | 一对象多文档、一文档一 owner、跨租户/伪造 owner 拒绝；角色撤销/模块停用/归档后不能读写；业务原权限不被新模块放宽 |
| 资源 R0/R1 | 稳定句柄/引用不变；预览、下载、管理分开；两资源整批准入、幂等/部分故障、旧匿名 URL/源站/已知 CDN 失效；真实 local/对象存储与可靠审计 |
| 内容工具 | 确定性工具选择、缺 provider、恶意 MIME/扩展伪装、无权下载、文件替换后历史字节不变、薄封装不再实现第二调度器 |
| 富文本协作 | 两名不同人员交错编辑，只读连接不能写；票据过期/重放、旧 room/lease 拒绝；用户切换/销毁不留订阅 |
| 保存与恢复 | PHP commit 水位覆盖本地修改后才显示已保存；同 storeId 同结果、不同摘要拒绝；CAS 冲突、DB/网络未知、Node 重启/背压、屏障超时和旧 epoch 不能覆盖新状态 |
| 投影与前端 | 合法 schema/大小、媒体句柄、HTML/URL 清洗、投影来自同一 Yjs 状态；失权后的响应/缓存/原件不能被继续交付 |
| Edition | 多租户作为完整功能回归目标；Standalone 跑自己的打包投影/关键创建安装登录协作/停启升级路径；共同逻辑证据可复用，Edition 专属行为不得跳过 |

每项证据记录源码/lock/环境/身份、命令、退出码、有效测试数/断言和日志摘要；mock 不证明真实事务、存储访问、撤权或协同。公开发布资格不在本轮终点内，不因 dev 已推送宣称正式发行。

## F. 失败、恢复与必须停止的边界

- 普通代码/类型/测试失败：主控定位根因、在当前写集中修复，批量稳定后重跑受影响检查；不能删断言、降类型或改安全合同求通过。
- 临时网络/服务失败：只对幂等读或已核旧结果的操作做有界退避（默认最多三次，尊重上游 Retry-After）；结果未知先查询原 Job/任务/提交，不启动第二个同类写入。确定性失败无新原因不反复重试。
- 进程或上下文中断：保存当前 run/task/session、各仓提交/脏差异、Job、写集、资源租约、最后成功断言与下一原子动作；使用精确原会话恢复，不用“最近一个会话”猜测身份，不重做有效任务。
- 子代理失联：先查实际进程/Job 与写入者。未证明原写入者终止或完成交接前，不能让新代理接手同一写集；确认终态后检查其产物再决定续做，不能覆盖现场。
- 源码并发前进：在自己的工作树先整合新提交，保留双方修改；只重验受影响部分；合入 dev 与推送分别检查。响应未知查询远端，禁止强推/reset/stash 他人工作。
- 真正硬阻塞：缺失只能由用户提供的认证、费用/许可选择、生产/客户数据操作、明确安全/权限拒绝、无法判定数据恢复策略、资源归属不明。只暂停依赖项，继续其他独立任务；不能用换执行器或关闭沙箱绕过拒绝。
- 所有剩余任务均硬阻塞时，输出 BLOCKED、已完证据、最小缺口、受影响任务和精确恢复点；不要无限轮询、声称完成或承诺网页关闭后自动继续。可重复使用的恢复计划不是已经启动的后台执行器。

## G. 状态记录与最终完成定义
